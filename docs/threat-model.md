# Threat model

## Protected assets

- Operator intent and approval authority
- Integrity of proposals, synthetic state, evaluation evidence, and release records
- Confidentiality of any future credentials or sensitive evidence
- Availability and auditability of the incident workflow

## Trust boundaries

The model, retrieved content, user artifacts, MCP payloads, external packages, model artifacts, and rendered evidence are untrusted. The deterministic policy reference monitor, approval store, executor, immutable evaluation manifests, and repository controls form the trusted computing boundary for this baseline.

## Principal threats and controls

| Threat | Baseline control |
|---|---|
| Indirect prompt injection or poisoned runbook | Full retrieval is retained for audit, but only trusted-kind telemetry/status enter the decision context; the agent then extracts allowlisted facts only; prose is never authority |
| Aggregate attack metrics hide a defense-stage gap | Baseline-0026 separately grades filtered hostile guidance, exposed hostile in-band evidence, and adversarial cases without instruction-bearing content across bounded outcomes and both splits; observed attempt flags must match the frozen catalog stage, so weakened filtering or hidden exposure fails closed rather than earning coverage |
| A defense-stage metric mislabels guidance never retrieved as guidance filtered | BASELINE-0028 freezes an additive four-stage metric that uses exact declared attack IDs plus each attempt's retrieval audit to separate `guidance_not_retrieved` from `guidance_retrieved_filtered`; mixed trials, missing identities, ambiguous catalog stages, and observed/catalog mismatch fail closed. The existing three-stage metric remains intact for historical compatibility. |
| Completeness-only retrieval reporting hides extra-record burden or attack rank | BASELINE-0029 freezes additive expected-document-share, extra-record, expected-rank, guidance-rank, in-band-rank, conditional-safety, split, and cross-trial-ambiguity metrics before any retrieval change. Missing, malformed, duplicate, unknown, over-top-k, or mixed-trial identities fail closed. Expected IDs are required evidence, not exhaustive relevance labels, and no aggregate score can trade safety against utility. |
| Bounded retrieval improves focus by silently dropping required or adversarial evidence | BASELINE-0031 freezes the exact 2/1/1 caps and no-backfill rule before implementation, rejects score thresholds that lose development evidence, and requires same-manifest development and held-out exactness for required IDs, expected ranks, scenarios, terminal states, coverage, adversarial stages, behavior, policy, utility, attack success, reliability, latency, and cost. A failed candidate is excluded and retained; focus cannot trade away safety or completeness. |
| Default-retriever fingerprints are mistaken for universal candidate safety gates | BASELINE-0033 preserves all selected-v3 release gates and introduces a separate read-only admissibility overlay. Only the exact five frozen observational differences may be classified as control fingerprints; all other 131 Boolean gates, required cells, ranks, identities, policy, security, utility, trajectory, reliability, latency, and cost boundaries remain mandatory. The original remediate disposition and latency failure remain immutable, and admissibility cannot select or promote a candidate. |
| A retrieval micro-optimization changes freshness semantics, hides held-out tuning, or substitutes benchmark speed for product reliability | BASELINE-0034 freezes v4-exact returned IDs, ranks, caps, no-backfill, and audit shape before v5 exists. It forbids cross-request caching and held-out optimization, requires five independent development-only retriever benchmarks plus a balanced six-report whole-system comparison, and keeps retrieval, behavior, policy, security, utility, reliability, latency, and cost gates separate. V3 remains default unless every gate passes; failure is retained and excluded. |
| A historical release validator treats every later retrieval checkpoint as corruption, or a permissive successor rule erases frozen identity | BASELINE-0034 retains the first 121/131 regression stop, restores released retrieval bytes, and freezes a no-runtime lifecycle bridge first. The bridge accepts only the original SHA-256 or one precomputed v5 identity, requires a public receipt, exact v4/v5 development behavior, v3 default until selection, and no held-out access; unknown hashes, missing receipts, premature promotion, and malformed results fail closed. Historical reports, traces, dispositions, contracts, and release bytes remain immutable. |
| The adjudicator overwrites evidence, writes an alternate path, or mutates retained inputs | Default execution is in-memory. Explicit `--write` accepts only the frozen result path, refuses an existing destination, creates exclusively, binds every retained source identity, rechecks sources for mutation, and requires independent post-write verification. It has no runtime, model, tool, credential, network, approval, or execution authority. |
| Mechanical release labels smuggle a second product or security change | BASELINE-0033 freezes the release-identity transition separately after adjudication. Only four product identity files may reach precomputed successor hashes; the other 20 product runtime files and complete 24-file inventory are byte-bound. The package entry set and container base, required checks, receipt inheritance, security controls, and local-only boundary remain exact. Any added runtime file, candidate promotion, base change, dependency, or unenumerated product byte stops release. |
| Missing comparison-gate inventory is mistaken for a passing empty set | The exact BASELINE-0031 reports and receipts bind matching 136-gate inventories and the candidate remains excluded. BASELINE-0033 now requires the complete 136-gate inventory, the exact five allowed false fingerprint gates, and all 131 remaining gates true; absent, substituted, duplicate, or extra gate identities fail closed. This hardening is read-only and cannot select the candidate. |
| Checkout line-ending drift makes local evidence unreproducible | The first BASELINE-0031 public clean clone failed closed before Docker when one retained historical manifest materialized as LF while the active release manifest had bound stale CRLF bytes. The failure is preserved. A file-specific binary attribute publishes the already-preserved original bytes; an independent fresh clone must pass the exact 153-file manifest before package or image construction. |

The canonical receipt binds the fresh scan to exact derived image ID `sha256:5cb0cb2d...`, the local-only tag/reference, scanner/version, command result, observation time, and zero critical/high count outside the SARIF body. Mutable tags, another digest, registry authentication, paid/private entitlement, export, push, publication, redistribution, secrets, and real infrastructure require new explicit authority and are outside this checkpoint. |
| Untrusted content forges its own trust tier, kind, provenance, or freshness | Tier metadata is authority only after authentication and normalization outside the model and retrieved content. The model cannot assign or upgrade a tier. Missing, malformed, future, or unverified metadata receives no privileged treatment; full selected identities remain auditable. |
| Retrieval jamming by query-matching untrusted guidance | Bound top-4 retrieval must reserve project-classified telemetry/status before untrusted guidance can consume the result budget; full returned identities remain auditable, and separate stress metrics grade evidence retention and benign utility rather than treating zero unsafe actions as sufficient |
| Stale project evidence crowds out current evidence | Freshness-priority retrieval reserves bounded capacity for project-classified telemetry/status that pass the shared one-hour rule before stale project records; stale-stress recall, retention, behavior, trajectory, and terminal state are exact-graded in both splits |
| Stale project payload reaches the agent or optional model | Full records remain audit-only; the deterministic decision policy projects stale records to exactly `id`, `kind`, and `observed_at`; field-level traces and frozen development/held-out graders require zero stale `title` or `content` exposure while preserving fresh payload and exact behavior |
| Stale or conflicting evidence | Shared fail-closed one-hour freshness window; missing, malformed, timezone-naive, or future timestamps receive no fresh treatment; missing evidence requests and conflict abstention remain bounded outcomes |
| Unauthorized action or capability escalation | Server-side allowlist and exact capability match; no model-controlled arguments |
| Forged or changed proposal | Canonical SHA-256 action hash bound to approval |
| Invalid, coerced, nonpositive, or overlong approval lifetime | The approval broker accepts only a JSON integer excluding booleans from 1 through 300 seconds and rejects invalid input before proposal status, approval storage, audit, trace, or incident mutation; frozen boundary cases grade the real HTTP surface and persisted terminal state |
| Caller forges approver identity or self-approves | Public v0.0.14 retains the measured gap. Missing, wrong, malformed, Bearer, duplicate, and prior-launch material fails uniformly before mutation. Direct Bearer/OAuth use remains excluded. |
| Cached execution result disclosed without approval authorization | A same-proposal idempotency-cache hit may return a result only after the supplied token hash matches a consumed approval for that proposal; wrong, missing, and cross-proposal material fails before result disclosure and without executor, state, idempotency, audit, or trace mutation; the original consumed token retains exact completed-retry utility even after expiry |

| TOCTOU and invalid transition | SQLite immediate transaction, precondition check, atomic state update, postcondition check |
| Credential exposure | The per-launch operator capability is supplied only through hidden input or standard input, reduced to an in-memory verifier, and excluded from arguments, environment, repository, package, persistence, audit, traces, logs, evaluation records, model/MCP surfaces, and dashboard; approval tokens remain hashed at rest and omitted from traces |
| MCP overreach | No approval or execution tool; closed-world annotations; enforcement ignores annotations as authority |

| Supply-chain compromise | Standard-library baseline; external-source gate and ledger before import; zipapp exact allowlist, fixed metadata, copied source bytes, embedded evaluation identity, per-entry hashes, independent verification, clean-clone rebuild identity, and public-download checksum gate |

## Explicit non-claims

The measured candidate validates deterministic synthetic boundaries but does not prove useful stochastic-model safety, real-source timestamp authenticity, universal prompt-injection resistance, strict numeric Pareto or latency dominance, or production reliability. Metadata can itself be malicious in a real system; source identity, kind, and timestamp therefore require external authentication and normalization. The baseline does not prove safety for a hostile operating system, compromised policy process, real production connector, or arbitrary third-party MCP server. Those require new threat analysis and gates.

Failure taxonomy is observability, not model improvement. A fully classified rejection remains a rejection; favorable failure counts cannot substitute for accuracy, utility, exact trajectory, repeated reliability, latency, cost, or separate attack-success evidence.
